# TenderLens AI — phased roadmap

Реализована только Phase 1. Следующие этапы — план, не готовые функции.
На каждом этапе добавлять относящиеся к нему проверки; Phase 12 объединяет
сквозные проверки и итоговую документацию.

## Phase 1 - project foundation
- [x] Структура Python 3.12, документация, шаблон окружения, Git.
- [x] Проверка состава файлов и импортов; без зависимостей и бизнес-логики.

## Phase 2 - Telegram bot
- [ ] Минимальный бот: /start, /help, конфигурация токена, обработка ошибок.
- [ ] Выбрать и добавить Telegram-библиотеку (кандидат: aiogram).
- [ ] Проверить обработчики без реального токена.

## Phase 3 - PDF upload and parsing
- [ ] Приём PDF, ограничения размера/типа, безопасное хранение.
- [ ] Извлечение текста с номерами страниц; обработка повреждённых файлов.
- [ ] Для сканов явно сообщать о необходимости OCR; не обещать его до реализации.

## Phase 4 - GigaChat API integration
- [ ] Общий контракт LLM-провайдера и первый адаптер GigaChat.
- [ ] Таймауты, ограниченные повторы, учёт расходов, тестовый подменный провайдер.
- [ ] Подготовить возможность отдельного адаптера YandexGPT; не добавлять заранее.
- [ ] Проверить настройки доступа и стоимость перед реальным вызовом.

## Phase 5 - structured tender extraction
- [ ] Схема фактов: заказчик, сумма/валюта, сроки, обеспечение, требования, источники.
- [ ] Проверка ответа LLM; отсутствующие данные — unknown/null, не выдуманные значения.
- [ ] Проверить на размеченных примерах.

## Phase 6 - tender scoring
- [ ] Профиль компании и явные версионируемые правила.
- [ ] Разделить соответствие, риски и полноту данных.
- [ ] Воспроизводимый результат с объяснением; не вероятность победы.

## Phase 7 - database
- [ ] SQL-схема, репозитории и миграции.
- [ ] Выбрать SQLite для локального MVP либо PostgreSQL по требованиям.
- [ ] Изоляция данных пользователей, дедупликация, хранение версий анализов.

## Phase 8 - RAG
- [ ] Фрагменты с привязкой к документу/странице, embeddings, индекс.
- [ ] Выбрать один векторный backend по объёму и ресурсам.
- [ ] Ответы с источниками и отказ при отсутствии подтверждения; тесты качества поиска.

## Phase 9 - tender source monitoring
- [ ] Контракт источника и один разрешённый источник для начала.
- [ ] Расписание, контроль частоты, дедупликация и уведомления по подписке.
- [ ] Обработка изменений и недоступности; не обходить ограничения площадок.

## Phase 10 - FastAPI
- [ ] HTTP-слой поверх существующих services, без дублирования логики.
- [ ] Валидация, авторизация, изоляция пользователей, состояния фоновых задач.
- [ ] Контрактные проверки API.

## Phase 11 - Docker
- [ ] Dockerfile и compose только для реально реализованных сервисов.
- [ ] Секреты вне образа, непривилегированный процесс, volumes, health checks.
- [ ] Проверка воспроизводимого запуска.

## Phase 12 - tests and documentation
- [ ] Unit, integration и end-to-end проверки, набор оценки LLM/RAG.
- [ ] Инструкция запуска, примеры без конфиденциальных данных, ограничения.
- [ ] Демонстрация и описание реальной роли разработчика; публикация по запросу.
