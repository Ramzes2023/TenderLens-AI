## TEK-Torg

Предоставленное пользователем описание [официальной инструкции](https://www.tektorg.ru/storage/files/3/Общие/API/Инструкция%20к%20API%20ТЭК-Торг.pdf)
указывает read-only [SOAP](https://api.tektorg.ru/procedures/soap) и
[WSDL](https://api.tektorg.ru/procedures/wsdl), operation `procedures`, wrapper
`exportRequestType`, фильтры и поля пагинации. Сам PDF/WSDL в этой работе не
загружался и независимо не проверялся. Это не подтверждение доступности или
разрешения доступа. Сервис публикации заказчиков не используется.

`app/sources/tektorg.py` предоставляет строгий парсер извлечённого UTF-8
ненеймспейсного XML-фрагмента, ограниченного 2 MiB. Корневой тег является
локальным соглашением извлечения, а не выдуманным SOAP response wrapper.
DTD/ENTITY, иные кодировки, namespace, неоднозначные обязательные поля,
неверные счётчики, более 500 записей на страницу и глубина более 16 отклоняются.
Пять страниц — локальный защитный предел, не заявленный предел API.
Идентификатор — JSON-пара `(sectionCode,id)`; повторы внутри/между страницами
отклоняются, одинаковые id в разных секциях допустимы. Поддерживается ограниченный
префикс страниц начиная с первой: полнота экспорта не гарантируется.

Сохраняются SHA-256 исходного фрагмента и XML записи. Офлайн-источник по умолчанию
выключен; для TenderNotice нужен явно переданный projector. Название, ссылка,
цена и даты не угадываются из неподтверждённых полей. Projector должен сохранять
происхождение отдельно либо в нормализованных данных; автоматического сохранения
сырого XML в БД нет. Ссылки проверяются по точному HTTPS host tektorg.ru или
www.tektorg.ru; проценты, credentials, fragments и нестандартные порты запрещены.
Это проверка безопасности ссылки, не доказательство существования страницы.

Офлайн-источник совместим с существующими TenderSource/TenderNotice/SourceRegistry
и validate_notice. Он намеренно не зарегистрирован в SourceCatalog, monitoring,
сетевой ingestion или durable scoring: иначе появились бы функциональные обещания
без подтверждённого протокола. Существующая архитектура не дублируется.
Будущий live-адаптер должен использовать существующий bounded HTTP transport,
ingestion и scoring после проверки доступа, а не отдельную сетевую инфраструктуру.

Нужны: полученный официальным путём WSDL/XSD с namespaces, binding, SOAP version,
SOAPAction, точным request/response envelope, типами и перечислениями фильтров;
правила аутентификации/доступа; допустимый успешный обезличенный ответ и Fault;
документированные поля названия и публичной ссылки; правила нумерации пустых
страниц, обновлений, лимитов и согласованности пагинации. Проверка фильтров сейчас
покрывает только известные имена, простые текстовые ограничения и локальные bounds;
wire XML не генерируется. Следующий официальный шаг — запросить этот пакет и
подтверждение права read-only экспорта у технической поддержки TEK-Torg.

## Roseltorg

[Официальная публикация о поиске](https://www.roseltorg.ru/knowledge_db/systems/notes/na-roseltorg-poyavilas-vozmozhnost-sokhranyat-parametry-poiska)
подтверждает поиск государственных, корпоративных и коммерческих закупок,
но не публичный API. В просмотренных локальных файлах app/docs/tests (без файлов
ЕИС/B2B) проверенного контракта не найдено. Адаптер не создан.
Запросить у площадки официальный read-only API/export, условия доступа, схемы,
реальные обезличенные ответы, pagination/identity и публичные ссылки. Для HTML
нужны разрешённые достоверные снимки и документированная стабильность разметки.

## Fabrikant

[Публичный реестр](https://www.fabrikant.ru/) и ссылки на интеграцию поставщика/
заказчика не доказывают наличие публичного read-only tender API. Локального
проверенного контракта не найдено; адаптер не создан. Официальный следующий шаг:
запросить API/экспорт чтения реестра, лицензию/доступ, XSD или JSON schema,
обезличенные ответы, pagination, уникальные идентификаторы и правила ссылок.

## Проверка

`tests/test_ru04b_tektorg.py`: все положительные данные **synthetic per documented
schema**, не authentic live snapshots. Покрываются provenance, identity, opt-in,
совместимость протокола/реестра, пагинация, повторы, XML/XXE, URL и projector.
Pytest в Codex не запускался; выполнение тестов и полный regression suite на host
остаются обязательными. Python/py/python3 и локальная .venv в доступной среде
не обнаружены, поэтому автоматическая синтаксическая проверка также не выполнена.
Выполнена ручная самопроверка кода и списка изменённых файлов.

### Исправление предыдущей офлайн-работы

Проверка URL теперь отклоняет credential-параметры и с пустым значением
(`token=`), и без знака равенства (`ACCESS_TOKEN`). Проверка XML отклоняет
namespace-атрибуты, включая `xml:lang`, также внутри записи процедуры.
Добавлены синтетические отрицательные проверки этих случаев и положительная
проверка публичного URL с обычными query-параметрами; существующие assertions
не ослаблены. Ограничения размера, DTD/XXE и идентичность `(sectionCode,id)` сохранены.

Подтверждённая host-диагностика: `36 passed, 2 errors in 0.72s`; две ошибки
`ValueError: the environment variable is longer than 32767 characters` возникают
до вызова парсера из-за ограничения переменных окружения Windows. В текущем
тестовом файле нет явного `setenv`, но большой bytes-параметр может попасть в
имя параметризованного теста и переменную pytest `PYTEST_CURRENT_TEST`.

Большой payload перенесён из параметризации внутрь отдельного теста:
XML передаётся непосредственно в `parse_export_fragment` как bytes, без
переменных окружения. Проверяется принятие корректного XML ровно в 2 MiB,
его SHA-256, XML записи и идентичность `(sectionCode,id)`, а также отклонение
payload на один байт больше лимита и прежнего невалидного большого payload.
Существующие отрицательные проверки DTD/XXE, URL, namespace и пагинации
сохранены. Контракт парсера и его защитные ограничения не изменены.

Pytest при исправлении не запускался по требованию пользователя. Результат
повторного host-прогона пока не получен. Host runner должен явно исключить
только три устаревших теста, ожидающих миграцию 13:
- `tests/test_jobs.py::test_historical_migration_checksums_are_frozen`
- `tests/test_postgresql_phase24s2b3_harness.py::test_repository_setup_offline_sqlite_smoke`
- `tests/test_postgresql_phase24s2b3_harness.py::test_complete_case_logic_offline_with_sqlite_and_process_doubles`

Миграция 14 `source_observations` уже существует в Git BASE; миграции и эти
три теста в данной работе не изменялись. TEK-Torg остаётся офлайн XML foundation
с синтетическими данными, без live feed и проверки API/WSDL.
Roseltorg и Fabrikant остаются BLOCKED.
