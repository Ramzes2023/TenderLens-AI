# VALYQON AI — проверенный источник в отдельном контуре (27 октября 2026)

## Что подключено

Реальный российский источник **MikroTon** (`mikroton_tender`) подключён к штатной цепочке VALYQON: официальный публичный HTTPS API → защищённый арендованный Worker → долговечная SQLite база → поиск в интерфейсе. Его адаптер и внутренние обработчики **уже присутствуют в `main`**. Этот PR добавляет воспроизводимый **изолированный контур запуска с явно включённым единственным источником**, а не ещё один парсер или имитацию.

Свидетельство: [PR #311](https://github.com/Ramzes2023/TenderLens-AI/pull/311) и его `real-origin-worker-guest-api` GitHub job: реальные записи, поиск с профилем компании, сохранение и защита другой организации. Дата свидетельства — 26 октября; площадка может оказаться недоступной сегодня, поэтому live CI этого PR обязан получить их заново.

## Безопасные границы

- **НЕТ** изменений рабочего сайта, production-конфигурации, основной базы или пользовательских аккаунтов.
- **НЕТ** оплаты, реального Telegram, внешних email, ИИ или автоматических клиентских уведомлений. Только локальный Mailpit.
- Docker Compose использует **отдельный** именованный volume и только loopback порты `18965` и `18966`, без доступа к старому review `18865`.
- По умолчанию запускаются лишь API, Worker и Mailpit. **Загрузка тендеров начинается только после явной одноразовой постановки утверждённого источника в очередь**.
- Стандартные флаги других источников остаются false. Данные MikroTon не называются ЕИС; это коммерческий источник, а не федеральная площадка ЕИС.
- Исторический green GitHub не равен доказательству сегодняшней доступности. Если текущий источник отвечает ошибкой/пустым списком, оператор не должен заменять сведения фейковыми.

## Как устроено (только для отдельного оператора QA)

Из корня репозитория с Docker Desktop, без загрузки сторонних скриптов:

```powershell
docker compose -p valyqon-ready-sources -f ops/ready_sources/compose.yaml config --quiet
docker compose -p valyqon-ready-sources -f ops/ready_sources/compose.yaml up -d --build api worker mailpit
docker compose -p valyqon-ready-sources -f ops/ready_sources/compose.yaml run --rm --no-deps enqueue
docker compose -p valyqon-ready-sources -f ops/ready_sources/compose.yaml ps
```

API: `http://127.0.0.1:18965/dashboard`. Локальный Mailpit для тестовой регистрации: `http://127.0.0.1:18966/`.

Каждая операторская постановка ограничена проверенной `RU_APPROVED_SOURCES` allowlist и включённым флагом. Повтор внутри того же UTC часа идемпотентен. Статус смотрят через `python -m app.sources.enqueue --status <ID>` в том же одноразовом контейнере; если состояние не `succeeded`, никаких утверждений о загрузке не делается.

Если нужно удалить **только** этот изолированный контур, не затрагивая существующие приложения:

```powershell
docker compose -p valyqon-ready-sources -f ops/ready_sources/compose.yaml down
```

Не добавляйте `-v`, если хотите сохранить тестовые аккаунты и базу в выделенном volume. Это не инструкция по production-деплою.

## Что НЕ доказано

Этот запуск не подтверждает коммерческое выставление счетов, Telegram user delivery, subscriber opt-in, полный production Worker, HTTPS-домен и оплату. Эти этапы находятся за отдельными release gates. Не объединять PR, если его собственный live workflow красный.
