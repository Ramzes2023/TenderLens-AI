# RU-02A: сравнение наблюдений российских закупок

Независимый синхронный модуль `app/sources/ru_notice_changes.py` использует
только стандартную библиотеку Python. Он принимает явно предоставленные
сведения об извещениях и лотах 44-ФЗ / 223-ФЗ, не определяя применимость закона.

## Публичный интерфейс

Все публичные структуры — типизированные `frozen=True` dataclasses со slots.

- `ObservationKey(namespace: str, procurement_id: str, lot_id: str | None = None)`:
  идентификаторы передаются строками; ведущие нули значимы. Namespace задаёт
  согласованную область идентичности источника, например `eis:44-FZ`.
- `Observation(key, observed_at, values, complete_fields=(), source_revision=None,
  source_updated_at=None)`: `values` — mapping поддерживаемых полей;
  `complete_fields` — коллекция имён полей, полноту которых подтверждает источник.
  Время наблюдения и необязательное время обновления источника требуют aware datetime.
  Ревизия — непрозрачная непустая строка, а не числовой счётчик.
- `compare_observations(previous: Observation | None, current: Observation)`
  возвращает `ComparisonResult`. Первое наблюдение задаётся `previous=None`.
  Ошибки входа вызывают `ValueError` с названием поля и объяснением.
- `ComparisonResult`: `schema_version`, `key` текущего наблюдения, `status`,
  неизменяемые tuples `changes`, `unobserved_fields`, `issues`, а также
  `previous_fingerprint` (None для первого наблюдения) и `current_fingerprint`.
- `Change`: `field`, `change_type` (`added`, `modified`, `removed`),
  `previous_value`, `current_value`.
- `Issue`: `code`, `field` (или None для общей диагностики), `message`.

Версия схемы: `ru-notice-changes/1`. Порядок полей, событий и диагностики
фиксирован схемой, а не порядком входного mapping.

## Каноническая схема

| Поле | Допустимое значение кроме None | Сравнение |
| --- | --- | --- |
| title | непустая строка | точное |
| buyer | непустая строка имени заказчика | точное |
| buyer_inn | строка из 10 или 12 ASCII цифр | точное, без проверки контрольной суммы |
| price | конечный неотрицательный Decimal | числовое, без округления |
| currency | три заглавные ASCII буквы | точное, без справочника валют |
| deadline | date или aware datetime | дата с датой; UTC мгновение с мгновением |
| status | непустая строка статуса из источника | точное, без юридической интерпретации |
| okpd2_codes | коллекция строк кодов | множество |
| ktru_codes | коллекция строк кодов | множество |
| document_ids | коллекция явных идентификаторов документов | множество |

ОКПД2: 2 цифры, опционально `.NN`, затем `.N` или `.NN`, затем `.NNN`.
КТРУ: `NN.NN.NN.NNN-NNNNNNNN`. Это проверка синтаксиса, а не наличия кода
в актуальном классификаторе. Идентификаторы ключей и документов используют ASCII
буквы, цифры и `_.:/-`, начинаются с буквы или цифры. Они должны поступать из
проверенного поля идентификатора источника. Допустимый синтаксис не подтверждает
происхождение и не превращает URL в идентификатор закупки.

Пустые строки, окружающие пробелы и управляющие символы запрещены. Текст
не приводится к нижнему регистру и не нормализуется по Unicode: изменения
форматирования могут быть изменениями наблюдения. Float, bool, int и строки
в price запрещены; преобразование выполняет будущий адаптер до вызова движка.
None допустим для любого поля. Пустая коллекция отличается от None.

Коллекции копируются в отсортированные tuples уникальных строк. Дубликаты
элементов разрешены и устраняются, но учитываются в лимитах. Повторение имён
в complete_fields запрещено. Mapping копируется в read-only MappingProxyType,
маска — в frozenset. Входные списки, словари и значения не изменяются.

Лимиты: 4096 символов текста; 256 символов идентификатора или ревизии;
256 элементов в каждой коллекции до удаления дубликатов; суммарно 32768
символов строк значений, коллекций, ключа и ревизии; Decimal до 128 цифр
и абсолютного значения экспоненты 128; только 10 полей схемы. Генераторы
не принимаются. Эти пределы ограничивают обрабатываемые данные, но не
защищают от враждебных пользовательских реализаций Mapping/Collection/tzinfo.

## Неполные данные и события

Отсутствующий ключ — всегда «не наблюдалось», даже если имя есть в маске.
Это сочетание дополнительно даёт `missing_complete_value`. None без маски
даёт `unconfirmed_absence` и не устанавливает отсутствие. Только явный None
с полнотой подтверждает удаление значения поля.

Ненулевой скаляр можно сравнить независимо от маски. Ранее неизвестное поле
не становится событием added: для события нужна сравнимая предыдущая база,
например подтверждённый None.

Для списков документов и классификаций добавление элемента требует полноты
предыдущего списка, удаление — полноты нового. При неполных списках событие
содержит прежнее множество и результат только подтверждённых изменений.
Поэтому `Change.current_value` может отличаться от частичного списка нового
Observation: это результат применения доказанных различий, не восстановленный
полный снимок источника. `partial_collection` и unobserved_fields указывают
на оставшуюся неопределённость. Полностью пустой новый список подтверждает
удаление всех ранее наблюдавшихся элементов только при полноте этого поля.

Статусы:

- `first_observation`: предыдущей базы нет; events не создаются.
- `identity_mismatch`: ключи отличаются; сравнение значений запрещено.
- `out_of_order`: время наблюдения регрессирует, оба source_updated_at заданы
  и регрессирует время источника, либо разные отпечатки имеют одинаковое
  время наблюдения. Событий нет.
- `changed`: есть хотя бы одно подтверждённое событие; покрытие может быть неполным.
- `insufficient_data`: событий нет, но хотя бы одно поле не сравнимо.
- `unchanged`: все 10 полей сравнимы и равны; оба списка каждого коллекционного
  поля полны либо их отсутствие явно подтверждено.

unobserved_fields означает поля с недостаточным покрытием сравнения, включая
несовместимую точность дат и частичные коллекции. Пустое первое наблюдение всё
равно имеет статус first_observation и перечисляет все неизвестные поля.
Наблюдаемый текст «cancelled» — только изменение status, не заключение об
отмене закупки. Удаление документа из подтверждённого списка означает изменение
списка идентификаторов источника, не физическое уничтожение файла.

## Время, идентичность и происхождение

Сравниваются только точно равные namespace, procurement_id и lot_id.
Извещение без lot_id не совпадает с конкретным лотом. Ведущие нули не удаляются.
Движок не извлекает идентичность из URL, текста номера или ссылки на закон.
Адаптер отвечает за правильную идентичность, достоверность маски полноты и
соответствие наблюдений одной области источника.

Aware datetime канонизируется в UTC без догадки о часовом поясе.
Разные представления одного мгновения равны, включая время наблюдения.
Naive datetime запрещён. Date-only не расширяется до полуночи: сравнение
с datetime даёт `precision_mismatch`, без изменения deadline. Другие поля
при этом могут дать status changed. Date сравнивается как календарная дата.
Непредставимые в UTC крайние значения отклоняются.

source_revision хранится без сортировки; различие ревизий даёт
`revision_not_ordered`. Временной порядок устанавливается только по timestamps.
Если один source_updated_at отсутствует, движок не восстанавливает время
источника. По двум наблюдениям невозможно обнаружить возврат к давней ревизии
без регрессии timestamp. История и политика принятия снимков нужны вне модуля.

## Отпечатки

SHA-256 от ASCII JSON с фиксированными разделителями и отсортированными ключами:
версия схемы, точный ключ, присутствующие значения и маска полноты.
Пропущенное поле отличается от явного None. Порядок и повторы коллекций
не влияют на результат; Decimal с разными масштабами равны; отрицательный
ноль канонизируется как ноль. Decimal context не влияет на округление,
поскольку оно вообще не выполняется. Date и datetime имеют разные типовые
метки, datetime содержит UTC с микросекундами.

observed_at, source_updated_at и source_revision не входят в отпечаток:
это отпечаток доказательств значений и полноты, а не уникальный ID получения,
не подпись источника и не гарантия подлинности. Равные отпечатки неполных
наблюдений сами по себе не дают unchanged. Python hash() не используется.

## Синтетический пример

```python
from datetime import datetime, timezone
from decimal import Decimal
from app.sources.ru_notice_changes import ObservationKey, Observation, compare_observations

key = ObservationKey("eis:44-FZ", "0001234567890123456", "001")
previous = Observation(
    key, datetime(2026, 10, 13, 9, tzinfo=timezone.utc),
    {"price": Decimal("100000.00"), "currency": "RUB", "document_ids": ["doc-001"]},
    {"price", "currency", "document_ids"}, source_revision="r-001",
)
current = Observation(
    key, datetime(2026, 10, 13, 10, tzinfo=timezone.utc),
    {"price": Decimal("110000.00"), "currency": "RUB", "document_ids": ["doc-001", "doc-002"]},
    {"price", "currency", "document_ids"}, source_revision="r-002",
)
result = compare_observations(previous, current)  # changed, price и document_ids
assert "deadline" in result.unobserved_fields

# Для независимо установленной закупки 223-ФЗ:
other_key = ObservationKey("eis:223-FZ", "000987654321", None)
first = compare_observations(None, Observation(
    other_key, datetime(2026, 10, 13, 10, tzinfo=timezone.utc),
    {"title": "Выполнение работ", "status": "published"}, (),
))
assert first.status == "first_observation"
```

## Интеграция и границы

Будущие шаги: адаптер явных идентификаторов и canonical values; подтверждение
полноты на основании конкретного формата источника; хранение принятых снимков
с provenance; обработка out_of_order/insufficient_data до сохранения;
потребители подтверждённых events и их диагностик. Источник обязан дать timezone,
а при сомнении оставить date-only или неизвестное поле.

Не реализованы получение тендеров, подключение к ЕИС, полный охват 223-ФЗ,
обнаружение всех закупок, мониторинг, база истории, API/UI, уведомления,
проверка ИНН по контрольной сумме, классификаторные справочники, юридические
решения или AI. Нет сети, БД, чтения окружения/секретов и записи файлов.

Фокусная проверка, без bytecode и pytest cache:

```text
python -B -m pytest -p no:cacheprovider -q tests/test_ru_notice_changes.py
```

Тест импортирует модуль напрямую, не запускает адаптеры `app.sources` и
не требует их зависимостей. Проверка синтаксиса: `ast.parse` обоих Python
файлов; `compileall` и полный набор проекта для этой фазы не используются.
