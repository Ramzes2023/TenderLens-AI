# Изолированный RSS-адаптер ЕИС 223-ФЗ

Статус: кандидат для последующей интеграции; в приложение не зарегистрирован.
Существующие ЕИС 44-ФЗ, Telegram, каталог, ingestion и БД не изменены.
Новых зависимостей нет. Производственная работоспособность не подтверждена.

## Публичный интерфейс

Импортировать непосредственно из `app.sources.eis_223_rss`:

- `build_eis_223_rss_url(search_term)` — один URL; нормализация пробелов,
  UTF-8 percent encoding через `urlencode`, непустой запрос до 500 символов.
- `build_eis_223_rss_urls(search_terms, max_feeds=5)` — уникальные запросы
  без учета регистра; 1–20 фидов, рассмотрение первых 100 входных терминов.
- `Eis223RssSource(urls=(), timeout=30.0, ca_bundle_file=None)` — неизменяемый
  источник с фиксированным именем `eis_223`. Пустая конфигурация ничего не запрашивает.
- `source.for_search_terms(terms, max_feeds=5)` — отдельный экземпляр для
  ключевых слов профиля; пустой набор сохраняет статические URL.
- `await source.fetch(limit=20)` — записи, лимит 1–100, максимум 20 фидов;
  учитывается общий `page_limit`. Ошибки транспорта/XML вызывают существующий
  `SourceError`; частичные результаты при последующей ошибке не возвращаются.
- `parse_eis_223_feed(payload, feed_url=None)` — автономный офлайн-парсер.
- `Eis223Notice` — совместимый наследник `TenderNotice` с полями происхождения.

Пример для будущего вызывающего кода:

```python
from app.sources.eis_223_rss import Eis223RssSource

source = Eis223RssSource().for_search_terms(["алюминиевый профиль"])
# notices = await source.fetch(limit=20)  # Только после отдельного разрешенного live QA.
```

## Запросы и фактическое поведение

Endpoint: `https://zakupki.gov.ru/epz/order/extendedsearch/rss.html`.
Генерируемые параметры: `searchString`, `morphology=on`, `pageNumber=1`,
`fz223=on`. Параметр `fz44` отсутствует; конфигурации с ним отклоняются,
как и другой host/path, HTTP или неоднозначный фильтр `fz223`.
Редиректы отключены. TLS проверяется: `verify=True` либо путь к CA bundle.
Используется существующий `source_client` и его ограничения транспорта.
Адаптер ограничивает читаемый распакованный ответ 5 МиБ; общий транспорт имеет
собственные ограничения сетевых байтов, декодирования и времени. В bounded
режиме общий клиент может буферизовать до своего лимита перед локальной проверкой.

Повторно используется существующий RSS/Atom-парсер для заголовка, ссылки,
строки даты публикации и business summary. Дата не преобразуется и не проверяется
как календарная дата. Отклоняются malformed XML, HTML, посторонний корневой
элемент, DTD/entity declarations. Поддерживаются RSS, Atom и RSS RDF.
XML сначала ограничивается по размеру; пагинация и загрузка карточек отсутствуют.

GUID имеет приоритет над номером; номер извлекается как последовательность
11–20 цифр только из заголовка/ссылки. Это эвристика идентификатора, а не закона.
Описание поиска не используется для номера. Номер только в GUID сохраняется
как `external_id`, но не автоматически как `tender_number`.
При отсутствии GUID/номера используется стабильный SHA-256 ссылки либо
заголовка, даты и описания. Длинный GUID хешируется без усечения с коллизией
общего префикса. Полный нормализованный GUID доступен в `raw_guid`.
Дубликаты удаляются по `(source, external_id)` внутри ответа и между фидами;
сохраняется первая запись. Разные GUID одного номера остаются разными записями.

Отсутствующий заголовок получает существующий placeholder; ссылка — пустую
строку; отсутствующие даты и другие значения — `None`. Поля customer, amount,
currency, deadline и region намеренно остаются `None`: этот этап не проверяет
их семантику в RSS 223-ФЗ. Лоты и документы не создаются.

## Происхождение и доказательства

- `source=eis_223` отделяет identity от существующего `eis` для 44-ФЗ.
- `feed_url` хранит запрос, `raw_guid` и `raw_description` — полный очищенный
  текст соответствующих полей, а не исходные XML/HTML байты.
- `requested_law=223-FZ` означает намерение фильтра источника. При прямом
  офлайн-парсинге произвольного XML это контекст адаптера, не факт HTTP-запроса.
- `observed_law` заполняется только явным указанием «Размещение выполняется по:
  223-ФЗ» или «44-ФЗ» в описании; противоречие сохраняется и не исправляется.
  Поисковая метаинформация «Закупки по» не считается подтверждением.
- `independently_verified_law` всегда `None`. Длина номера, тип способа закупки
  и фильтр не доказывают правовую классификацию. Записи не отбрасываются при
  отсутствии или противоречии наблюдаемого закона.

По предоставленным оператором данным, RSS 44-ФЗ и кандидат с `fz223=on`
вернули HTTP 200, корректный RSS XML и по 200 записей. Пример кандидата:
«Other procurement method, number 32616463738». Это внешнее свидетельство
доступности RSS. В рамках этой задачи сеть не использовалась; свидетельство
не подтверждает полноту, актуальность или закон каждой записи.
Одна страница и ограниченный набор терминов не обеспечивают общенациональный охват.

## Дальнейшая интеграция

Отдельной задачей потребуется регистрация `SourceRegistration` с ключом
`eis_223`, транспортом RSS, юрисдикцией RU и языком ru. Возможности:
keyword_search=True, pagination/documents/incremental_sync=False,
authentication_required=False. Автоматический запуск сейчас отсутствует.
Текущий `SourceCatalog.fetch` применяет профильные термины только к ключу `eis`;
для 223-ФЗ понадобится явное подключение соответствующего маршрута позже.

Будущий ingestion должен сохранить source и поля происхождения, проверить
сериализацию наследника модели, сопоставление идентификаторов и правила обновлений.
Telegram и уведомления — последующая отдельная задача после проверки ingestion.
Перед подключением необходима независимая live-проверка покрытия, фильтра закона,
описаний/номеров, задержек, пропусков, дублей, редиректов и поведения ЕИС под нагрузкой.
Синтетические тесты доказывают только локальные контракты реализации.
